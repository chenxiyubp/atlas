## 一条内容该放哪：判定表

| 情况 | 去处 |
| --- | --- |
| 读代码就能发现（目录结构、某函数在哪） | **不写** |
| 读代码会得出**错误**结论（为什么不能把构建"优化"回单文件、为什么各 fallback 故意不同） | CLAUDE.md |
| 团队做法与取舍 | skill |
| 长规格、命令清单、流程 | `docs/` 或 `CONTRIBUTING.md`，CLAUDE.md 只留指针 |
| 必须确定性发生且适合自动检查 | 用 **hook / 测试** 实现，并保留必要的权限、目的与使用边界说明 |

官方的 include / exclude 清单：

**该进 CLAUDE.md**：猜不到的 bash 命令、与默认不同的代码风格、测试方式与偏好的 runner、
仓库礼仪（分支命名、PR 约定）、项目特有的架构决策、开发环境怪癖（必需的环境变量）、
常见 gotcha 与非显然行为。

**不该进**：读代码就能得出的、语言标准约定、详细 API 文档（给链接）、频繁变动的信息、
长篇解释或教程、逐文件的代码库描述、"写干净的代码"这类自明实践。

## CLAUDE.md 的自检信号

- **Claude 反复做你明令禁止的事** → 先查这条是否真的被加载、有没有和别处冲突，再改写；不要靠加粗和堆叠。
- **Claude 问的问题 CLAUDE.md 里明明写了** → 表述有歧义，改写法。
- **不加这条 Claude 也做对** → 删；需要确定性保障的检查交给 hook / 测试。

把 CLAUDE.md 当代码对待：出问题时审查它、定期剪枝、改完观察行为是否真的变了。

需要提高遵守度时可以加 `IMPORTANT` / `YOU MUST` 之类的强调——但这是**局部**手段，
不是往里堆更多条目的理由。

## skill 撰写硬约束（官方）

**frontmatter**

- `name`：≤ 64 字符，只能小写字母 / 数字 / 连字符，不能含 XML 标签，
  **不能含保留词 `anthropic` / `claude`**。
- `description`：非空，≤ 1024 字符，不能含 XML 标签。**必须第三人称**
  （描述会被注入 system prompt，人称不一致会影响触发判断）。
  必须同时说清**做什么**和**何时用**——Claude 靠它从上百个 skill 里选一个。

**正文**

- SKILL.md 保留触发后的共同流程和必要边界；按独立任务拆分参考文档，不按行数截断内容或删掉接口与必要步骤。
- **引用只允许一层深**。SKILL.md → a.md → b.md 这种嵌套会让 Claude 用 `head -100`
  之类的方式部分读取，拿到残缺信息。所有引用文件都从 SKILL.md 直链。
- 超过 100 行的引用文件**在开头放目录**，这样部分读取时也能看到全貌。
- 不写会过期的时间性内容；历史信息放进折叠的 "old patterns" 段。
- 术语前后统一（别混用 "字段 / 框 / 元素"）。
- **不要给一堆并列选项**。给一个默认，再给逃生口。

**默认假设：Claude 已经很聪明。** 每段都问："这段解释真的必要吗？它值这些 token 吗？"

## 渐进式披露的三种组织方式

1. **概览 + 引用**：SKILL.md 给快速上手，细节指向 `FORMS.md` / `REFERENCE.md`。
2. **按领域分目录**：`reference/finance.md`、`reference/sales.md`——问销售时不必加载财务。
3. **条件展开**：基础内容直接写，高级用法给链接。

关键性质：**文件不被读就不消耗 token**。所以可以放心 bundle 完整 API 文档、
大量示例、大数据集——只有真正读取时才付费。脚本更省：**执行**脚本只有输出进上下文，
脚本本身不进。

所以在指令里要**说清意图**：「运行 `x.py` 来抽取字段」（执行）vs
「见 `x.py` 了解抽取算法」（当参考读）。

## 自由度校准

按任务的**脆弱性与可变性**匹配指令的具体程度：

- **高自由度**（文字说明）：多种做法都对、依赖上下文判断。例：代码评审流程。
- **中自由度**（伪代码 / 带参数的脚本）：有偏好模式，允许变化。
- **低自由度**（固定脚本、少参数）：操作脆弱、必须严格按序。例：数据库迁移。

比喻：悬崖间的窄桥要护栏；开阔地给方向就行。

## 上下文管理与子 agent

**上下文是最重要的资源**，性能随占用上升而下降。

- 并行或需要隔离上下文时用子代理（无边界的探索、独立的调查、有价值的独立评审）；单文件改动或顺序任务直接做。子代理回报结论、证据位置、实际改动、验证结果与阻塞。
- 长任务用**结构化笔记**（写到上下文之外的文件）维持连贯；不相关的新任务可用新上下文，先保存目标、授权、已验证结论与待办。
